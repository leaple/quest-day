# QUEST DAY 2.0 — 로그인 · 회원가입 · 게스트 시작

기존 QUEST DAY 앱과 Supabase 프로젝트는 **그대로 유지**합니다. 별도 SQL 마이그레이션은 필요하지 않습니다.

## 시작 화면

기존 기기에서 퀘스트 기록이나 실시간 친구 사용 흔적이 확인되면 신규 로그인 화면으로 막지 않고 **바로 기존 앱을 엽니다**. 저장한 기록을 지우지 않습니다.

처음 접속하는 새 기기/브라우저에서는 다음 메뉴를 보여줍니다.

- **로그인:** 기존 이메일 계정으로 로그인하여 QUEST DAY 계정의 친구·채팅·게임 저장본에 다시 접근합니다.
- **회원가입:** 이메일·비밀번호(10자 이상)를 등록합니다. 이메일 확인을 사용 중이라면 메일 인증 완료 후 로그인하거나 코드로 확인합니다.
- **게스트로 시작:** 이메일이나 비밀번호 없이 로컬 게임으로 시작합니다. 앱을 실행하면 Supabase에 자동 연결되고, 로그인하지 않았다면 임시 익명 계정이 생성됩니다. 게스트 모드 선택만으로 퀘스트 원문·캐릭터 구매 내역 등 게임 전체 기록을 클라우드에 업로드하지는 않습니다.
- **설정 → 계정 및 로그인:** 게스트가 나중에 계정을 만들거나 기존 계정으로 전환할 수 있습니다.

## Supabase Auth 설정

기존 QUEST DAY Supabase 프로젝트의 Authentication 영역에서 **Email** 제공자가 활성화되어 있어야 합니다. 이메일 인증 사용을 권장합니다.

**중요: Authentication → URL Configuration에서 두 곳을 반드시 같은 QUEST DAY 앱 주소로 설정하세요.**

- **Site URL:** `https://leaple.github.io/quest-day/`
- **Redirect URLs 목록에 추가:** `https://leaple.github.io/quest-day/`

[QUEST DAY Supabase URL 설정 열기](https://supabase.com/dashboard/project/yivabefhugxvigbsgkts/auth/url-configuration)

Supabase 기본 메일의 **Confirm Email** 링크는 인증 후 프로젝트의 Site URL 또는 허용된 Redirect URL로 돌아옵니다. 앱 코드에서는 회원가입과 이메일 연결 요청 모두 `emailRedirectTo`를 같은 QUEST DAY 주소로 지정합니다. 잘못된 주소로 연결된 이전 인증 메일은 새 메일을 요청하고 테스트하세요.

**Authentication → Emails → Email Templates**의 Confirm sign up / Change email address 템플릿은 기본적으로 `{{ .ConfirmationURL }}` 인증 링크를 포함합니다. 기본 메일에는 별도의 숫자 인증코드가 없을 수 있으며, 코드 입력은 메일에 `{{ .Token }}`이 실제 포함되도록 템플릿을 변경한 경우에만 사용하세요.

GitHub Pages에 Supabase의 secret/service-role key를 넣지 마세요. 앱은 이미 설정된 Publishable key만 사용합니다.

익명(게스트) 계정에 이메일을 **그대로 연결**하려면 Supabase의 **Allow manual linking**도 활성화해야 할 수 있습니다. 이 경우 `auth.updateUser({ email })`을 호출해 같은 Auth 사용자 ID를 유지하고, 이메일 인증 후 비밀번호를 설정합니다.

## 데이터 보호 원칙

1. **기존 사용자의 로그인 상태와 로컬 저장소 유지:** `quest-day-mvp-v1`, 실시간 친구 연결, 클라우드 사용자 ID 등은 변경하거나 자동 삭제하지 않습니다.
2. **기존 익명 계정을 가입 상태로 전환:** 같은 익명 ID에 이메일을 연결하면 친구 관계, 채팅 및 클라우드 기록을 유지할 수 있습니다.
3. **기존 이메일 계정으로 전환:** 이전 익명 ID와 새 계정 ID가 다를 수 있습니다. 이 경우 기존 익명 계정의 친구 관계는 자동 이전되지 않음을 안내합니다. 로컬 퀘스트·캐릭터는 지우지 않고 클라우드의 버전 비교와 충돌 선택을 통해 처리합니다.
4. **연결과 게임 클라우드 저장을 구분:** 앱 실행 시 서버 자동 연결로 친구 프로필 요약(닉네임·캐릭터·레벨·XP·퀘스트 완료 수·연속 달성)을 서버에 전송할 수 있습니다. 친구가 되면 상대방에게 이 요약이 보입니다. 퀘스트 제목·개별 완료 이력·골드·구매 기록 전체는 별도 게임 클라우드 동기화가 활성화된 계정에만 저장됩니다. 기존 클라우드 기록과 로컬 기록이 다르면 충돌 보호 기능이 작동합니다.
5. **오프라인 선택 유지:** 사용자가 친구 화면에서 명시적으로 연결을 중단한 경우 재실행 시에도 오프라인 모드가 유지됩니다. 일반적인 연결 오류는 앱에서 자동으로 다시 시도합니다.
6. **손실 방지:** 로그아웃으로 익명 계정이 영구 접근 불가능해지는 사고를 막기 위해 자동 로그아웃 버튼은 제공하지 않습니다. 계정 전환에는 확인 안내가 들어갑니다.

## 테스트

1. 기존 사용 중인 아이폰에서는 앱을 삭제하거나 브라우저 기록을 지우지 말고, 기존 퀘스트가 그대로 열리는지 확인하세요.
2. 테스트용 시크릿/개인정보 보호 브라우징 창 등 별도의 저장 공간에서 [QUEST DAY](https://leaple.github.io/quest-day/?qd_update=23)를 처음 열어 시작 화면을 확인하세요.
3. **게스트로 시작**을 누르고 퀘스트를 만든 뒤 앱을 다시 열어 유지되는지 확인합니다(일반 브라우저 프로필에서).
4. 이메일 가입은 실제 사용할 이메일로만 테스트하세요. 인증 메일 빈도 제한이 있거나 SMTP를 구성해야 할 수 있습니다.
5. 기존 계정으로 로그인한 뒤 **설정 → 계정 전체 데이터 동기화**에서 기록 불러오기/충돌 선택이 정상 작동하는지 확인합니다.

기기 데이터 초기화, 앱 삭제 또는 공개 공유용 서비스 키 사용은 필요하지 않습니다.

공식 문서: [Supabase Anonymous sign-ins](https://supabase.com/docs/guides/auth/auth-anonymous) · [Email/password sign-in](https://supabase.com/docs/guides/auth/passwords) · [Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls).

## 서버 자동 연결 (2.0 후속 업데이트)

- 네트워크에 연결된 경우 앱 실행과 동시에 Supabase 인증·친구/채팅 연결을 시작합니다. 별도의 **실시간 친구 기능 켜기** 버튼을 누르지 않아도 됩니다.
- 인증되지 않은 방문자는 임시 익명 사용자로 연결합니다. 이전에 로그인한 사용자는 저장된 인증 세션을 그대로 사용합니다.
- 연결 오류가 발생하면 재접속을 자동으로 시도하며, 서비스가 끊겨도 기기 안의 퀘스트 기록은 사라지지 않습니다.
- **오프라인 모드**를 명시적으로 선택한 사용자의 선택은 존중합니다. 친구 화면에서 다시 연결할 수 있습니다.
- 게임 전체의 클라우드 저장 여부는 별도로 관리하므로, 자동 서버 연결 자체가 모든 퀘스트 기록 업로드를 뜻하지는 않습니다.

## 2.0 이메일 인증 오류 수정 (업데이트 v24)

- **입력값 보존:** 계정 관리와 기존 계정 보호 화면에서 인증 메일을 요청해도 이메일 입력값을 지우거나 열린 인증 폼을 닫지 않습니다.
- **인증 방식:** 기본 메일에서는 숫자 코드 입력 대신 Confirm Email 링크 클릭을 안내합니다. 앱으로 돌아온 뒤 **메일 링크 인증 완료 확인**을 누르면 가입/계정 연결 상태를 확인합니다.
- **기존 게스트 전환:** 이메일 인증 후 새 비밀번호를 설정할 수 있습니다. 기존 익명 Auth 사용자 ID를 변경하지 않습니다.
- **인증 링크 오류:** 앱에서 callback 오류를 보여줍니다. Site URL/Redirect URLs을 수정한 다음 *새로 발송된 이메일*로 테스트하세요.
- 링크를 눌렀는데 다른 브라우저가 열렸다면 **원래 게임을 사용하던 브라우저나 홈 화면 앱**으로 돌아가 '메일 링크 인증 완료 확인' 또는 설정의 '메일 링크 인증 상태 확인'을 누르면 됩니다.
- 메일 앱이나 보안 필터가 링크를 미리 접속해 인증 토큰이 만료되는 경우가 있습니다. 이 경우 새 메일을 요청하세요.

관련 Supabase 공식 문서: [이메일 템플릿](https://supabase.com/docs/guides/auth/auth-email-templates), [리디렉션 URL](https://supabase.com/docs/guides/auth/redirect-urls), [익명 계정 전환](https://supabase.com/docs/guides/auth/auth-anonymous).

## 계정 관리 화면 통합 (v25)

QUEST DAY에는 **하나의 계정 관리 UI만** 남겨 두었습니다.

- 첫 실행: 로그인 / 회원가입 / 게스트 시작
- 기존 사용자: **설정 → 계정 및 로그인 → 계정 관리**
- 게스트: **현재 게스트 기록에 이메일 연결** → 메일 링크 인증 → 비밀번호 설정 (기존 Supabase 익명 사용자 ID 유지)
- 이메일 회원: **인증된 이메일 표시** / **비밀번호 설정·변경** / 다른 이메일 계정으로 로그인
- 성장 기록 동기화 보류 상태: 설정 계정 관리에서 복구 버튼 표시. 클라우드 게임 기록 충돌이 있으면 **계정 전체 데이터 동기화** 화면에서 먼저 해결해야 합니다.
- Supabase URL, Auth 설정, SQL, LocalStorage 게임 저장 키(`quest-day-mvp-v1`), 클라우드 계정 데이터는 변경하지 않습니다.

이전 1.8 `upgrade-1.8-stability.js` 파일은 복구를 위해 저장소에 남아 있지만, **index.html과 서비스 워커에서 더 이상 로드하지 않습니다.** 따라서 두 번째 이메일/로그인 폼은 생성되지 않습니다. `upgrade-1.9-cloud.js`는 기존처럼 별도의 클라우드 저장/충돌 관리 UI를 유지합니다.

테스트용 링크: https://leaple.github.io/quest-day/?qd_update=25

## 이메일 회원 클라우드 자동 저장 (v26)

- **이메일 인증이 완료된 계정**: 앱 실행 시 Supabase 계정 ID를 확인하고, 해당 ID의 전체 게임 저장본을 먼저 조회합니다. 별도 '동기화 허용' 버튼 없이 동기화를 시작하고 변경된 퀘스트·XP·캐릭터·구매·업적을 자동 저장합니다.
- **게스트**: 신규 계정은 게임 기록을 기기 로컬 저장소에만 보관합니다. 이메일 연결 후 인증 + 비밀번호 설정을 완료하면 같은 Supabase ID를 유지한 채 자동 백업을 시작합니다. 과거 버전에서 사용자가 명시적으로 게스트 클라우드 저장을 켠 경우 그 선택은 유지됩니다.
- **기존 서버 기록**: 항상 먼저 `qd_cloud_load`로 확인합니다. 기기의 기록이 정확한 기본 데모 퀘스트라면 서버 저장본을 가져오되, 사용자가 데모 퀘스트를 수정·삭제한 경우 사용자 작업으로 취급하고 두 기록이 다르면 충돌 선택을 보여줍니다.
- **다른 계정 전환**: 서버 저장본과 현재 기기 기록이 충돌하면 업로드/다운로드를 멈추고 '클라우드 기록 사용' 또는 '이 기기 기록 사용' 중 사용자가 결정하도록 합니다. 기록을 덮어쓰는 경우 기존 기록의 안전 보관본을 만들고, 서버 업로드는 버전(CAS) 검사로 보호합니다.
- **인증 실패/오프라인**: 인증 정보가 확인되지 않으면 게임 전체 기록을 업로드하지 않습니다. 기기 기록은 그대로 유지되고 재연결/재시도 가능합니다.
- **별도 서비스 설정 없음**: 기존 Supabase `quest-day-cloud-1.9.sql` 테이블과 RPC를 그대로 사용합니다. 새로운 SQL 마이그레이션, 별도 DB 또는 API 키는 필요하지 않습니다.

테스트 주소: https://leaple.github.io/quest-day/?qd_update=26

## 소폭 UI 조정 (v31)

- 오늘의 퀘스트 카드 최소 높이: **64px → 56px**. 카드 간격과 내부 여백도 줄이고, 완료 버튼의 44px 터치 영역은 유지합니다.
- 회원가입/이메일 연결 후 비밀번호 설정/기존 이메일 계정의 비밀번호 변경에서 **10~128자**를 허용합니다. Supabase 서버에 별도로 더 엄격한 비밀번호 정책이 설정되어 있다면 서버 정책도 충족해야 합니다.
- 사용자 퀘스트 배열과 클라우드 게임 데이터는 변경하지 않습니다.

# QUEST DAY 1.9 — 전체 게임 데이터를 계정에 자동 동기화

이제 퀘스트, 활동 기록, XP, 골드 계산에 필요한 보상·구매 기록, 캐릭터, 업적·설정 같은 **현재 게임 저장 데이터 전체**를 Supabase 계정에 보관할 수 있습니다. 친구·신청·채팅·파티는 기존 Supabase 서버에 그대로 저장됩니다.

## 1. 데이터베이스 추가 (필수, 한 번)

기존 QUEST DAY Supabase 프로젝트를 엽니다. **새 프로젝트를 만들면 안 됩니다.**

1. GitHub의 [quest-day-cloud-1.9.sql](./quest-day-cloud-1.9.sql)을 엽니다.
2. **전체 코드**를 복사합니다.
3. Supabase → **SQL Editor** → 새 쿼리에 붙여넣어 **Run**합니다.
4. **Success** 표시가 뜨는지 확인합니다. 이 스크립트는 기존 게임/친구 테이블을 지우지 않습니다.

클라우드 저장은 사용자 ID를 기준으로 한 행에 JSONB를 저장하며, Postgres RLS가 다른 계정의 기록을 읽을 수 없도록 제한합니다. 서버의 버전 번호(Revision)로 이전 기기에서 최신 기록을 덮어쓰지 않도록 보호합니다.

## 2. 처음 동기화 켜기

1. [QUEST DAY 최신 버전](https://leaple.github.io/quest-day/?qd_update=17)을 열고, **친구**에서 실시간 계정 연결을 확인합니다.
2. **설정 → 계정 전체 데이터 동기화 → 내 모든 기록 클라우드 동기화 시작**을 누릅니다.
3. 퀘스트 이름, 수행 기록, 캐릭터·구매 기록 등을 서버에 저장하는 데 동의합니다.
4. **☁️ 계정과 자동 동기화 중** 표시를 확인합니다.

그 뒤에는 저장 버튼을 따로 누르지 않아도 변경 사항을 기기에 즉시 기록하고 서버에도 자동 전송합니다. 앱이 닫힌 동안은 통신하지 않으며 앱을 다시 열면 동기화를 재시도합니다.

**중요:** 이 기능을 켜기 전에는 기존 데이터가 여전히 그 기기에만 있을 수 있습니다. SQL 실행 직후 모든 기록이 이미 계정으로 옮겨진 것은 아닙니다.

## 3. 다른 기기에서 이어서 플레이

1. 기존 기기에서 설정의 **QUEST DAY 계정 보호**를 통해 이메일 인증을 완료하고 비밀번호를 설정합니다.
2. 다른 기기에 QUEST DAY를 설치/접속합니다.
3. 친구 탭에서 실시간 연결을 켠 다음 설정의 **QUEST DAY 계정으로 로그인**을 실행합니다.
4. 같은 계정의 클라우드 저장본을 자동으로 조회하고 가져옵니다. 이 기기에 별도 진행 기록이 있다면 덮어쓰지 않고 선택 화면을 보여줍니다.

**익명 계정은 기기 변경 후 복구할 수 없습니다.** 이메일·비밀번호를 설정하는 것은 선택 사항이지만, 여러 기기에서 같은 계정을 쓰려면 반드시 계정에 재로그인할 방법이 필요합니다.

## 4. 안전장치

- **기존 로컬 기록 유지:** 원래 게임 저장 키 `quest-day-mvp-v1`을 그대로 사용합니다.
- **원격 저장본 버전 검사:** 서로 다른 기기에서 동시에 저장하면 버전 충돌을 확인하고 가능한 변경 사항은 병합합니다. 안전한 병합이 불가능하면 기록 선택 화면에서 사용자 확인을 받습니다.
- **초기 복원 보호:** 원격 기록으로 기기 기록을 교체해야 할 때는 내부 안전 보관본을 기록하려고 시도합니다. 보관할 공간이 부족하면 덮어쓰기를 중지합니다.
- **연결 오류:** 인터넷이 끊기면 데이터는 기기에 남으며, 앱 실행 및 인터넷 연결 복구 때 동기화를 재시도합니다.
- **게임 기록 전체 초기화:** 동기화가 켜진 경우 두 번 확인한 뒤 계정의 게임 저장본을 비웁니다. 다른 기기도 해당 변경을 받습니다.
- **백업·복원·앱 아이콘 다운로드 메뉴 제거:** 요청에 따라 설정에서 해당 버튼을 삭제했습니다. 현재 앱 아이콘 자체는 유지됩니다.
- **크기 제한:** 현재 클라우드 게임 저장본은 최대 5MB입니다. 너무 크면 업로드하지 않고 오류를 표시하므로 추가 최적화가 필요합니다.

## 5. 개인정보 주의

- 게임 저장본에는 **퀘스트 제목, 활동 날짜와 시간, 구매·성장 기록 등**이 포함될 수 있습니다. Supabase 서버가 이 데이터를 저장하고, 프로젝트 관리자에게는 접근 권한이 있습니다. **종단 간 암호화(E2EE)는 아닙니다.**
- 사용자의 동의 전에 전체 게임 데이터를 업로드하지 않습니다.
- 비밀번호·이메일은 게임 저장본에 포함하지 않습니다. 인증 정보는 Supabase Auth가 별도로 처리합니다.
- 기존 Supabase 프로젝트의 Publishable key만 브라우저 코드에 넣고 비밀 키는 절대 공개하지 않습니다.

## 6. 테스트

1. 원래 기기에서 퀘스트 완료 후 **설정 → 계정과 자동 동기화 중**을 확인합니다.
2. 같은 계정으로 로그인한 다른 기기에서 퀘스트 완료 기록과 캐릭터, 골드가 일치하는지 확인합니다.
3. 다른 기기에서 퀘스트를 하나 추가하고 원래 기기에서 추가되는지 확인합니다.
4. 두 기기가 동시에 같은 설정을 변경했다면 자동 병합 대신 충돌 안내가 나올 수 있습니다. 이 경우 원하는 기록을 선택합니다.

사용 중 데이터가 보이지 않더라도 앱을 삭제하거나 브라우저 데이터를 지우지 마세요. 먼저 설정의 계정 및 클라우드 연결 상태를 확인하세요.

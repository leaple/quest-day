# QUEST DAY 1.7 — 파티 / 응원 알림 / 주간 랭킹 / 친구 채팅 설치

이 문서는 **이미 QUEST DAY 1.6 실시간 친구 서버를 연결한 사용자**를 위한 추가 설정이에요.

## 적용 순서

1. Supabase에서 기존 QUEST DAY 프로젝트를 선택합니다. **새 프로젝트를 만들지 마세요.**
2. [quest-day-social-1.7.sql](./quest-day-social-1.7.sql)을 GitHub에서 열어 **전체 코드**를 복사합니다.
3. Supabase → **SQL Editor** → 새 쿼리에 코드를 붙여넣고 **Run**을 누릅니다.
4. 성공 메시지가 나오면 [QUEST DAY 최신 버전](https://leaple.github.io/quest-day/?qd_update=13)을 엽니다. 홈 화면 설치 앱은 종료했다가 다시 실행하세요.
5. 친구 탭 상단에 **🏆 랭킹 · ⚔️ 파티 · 🔔 알림 · 💬 채팅** 메뉴가 나타납니다.
6. 다른 기기에서 친구 신청·수락을 마친 뒤 테스트합니다.

**기존 1.6 SQL을 다시 실행할 필요는 없습니다.** 연결 설정인 `realtime-config.js`도 이미 작성했다면 다시 편집할 필요가 없습니다.

## 무엇이 추가되나요?

| 기능 | 이용 방법 |
|---|---|
| 주간 랭킹 | 친구와 나의 이번 주 새 XP·퀘스트 완료 수를 비교합니다. 월요일~일요일, 한국 시간 기준 |
| 파티 퀘스트 | 친구에게 공동 완료 목표 5·10·20개를 초대하고 친구가 수락하면 진행을 합산합니다 |
| 응원 알림 | 미리 정해진 응원 3종을 전송하고 친구 탭에서 수신을 확인합니다 |
| 1:1 채팅 | 서로 친구인 사용자끼리 텍스트 메시지를 주고받습니다. 1회 500자 제한 |

앱이 실행 중일 때 알림 영역과 화면 내 알림으로 알려줍니다. **백그라운드 푸시 알림은 아직 지원하지 않습니다.**

## 안전과 개인정보

- **서로 친구 수락을 완료한 사용자끼리만** 채팅·응원·파티 기능을 이용할 수 있습니다.
- 채팅은 텍스트만 지원하며, 낯선 사람 검색, 공개 채팅방, 파일·사진 전송 기능은 없습니다.
- 서버에 메시지 본문과 전송 시간, 친구 관계, 응원 기록, 파티 진행 상태, 매주 획득한 XP·완료 수가 저장됩니다. 이 채팅은 **종단 간 암호화(E2EE)가 아닙니다.**
- 전화번호·집 주소·학교·비밀번호 같은 개인정보는 채팅에 입력하지 않는 것을 권장합니다.
- 받은 메시지는 **신고**할 수 있고, 상대방을 **차단**하면 친구 관계가 해제되어 채팅이 중단됩니다. 신고 기록은 데이터베이스에 저장되지만 관리자에게 자동으로 즉각적인 제재가 실행되는 기능은 없습니다.
- 메시지는 서버에 저장되며 자동으로 며칠 뒤 삭제된다고 보장하지 않습니다. 서버 운영자가 데이터 보관·삭제 및 신고 대응 절차를 마련해야 합니다.
- SQL은 신규 소셜 테이블에 RLS를 적용하며 사용자는 해당 테이블에 직접 메시지를 삽입·변경할 수 없도록 제한하고 서버 함수(RPC)로만 보낼 수 있게 했습니다.
- 파티 퀘스트는 목표 완료 횟수를 합산하는 기능입니다. 공동 목표 달성으로 **추가 XP나 골드를 지급하지 않습니다.**
- 주간 랭킹은 설치 전 누적 XP가 아니라 **SQL 실행 이후 프로필 변경으로 새로 얻은 XP**부터 집계됩니다. 온라인 서버의 데이터가 계정 인증된 공식 기록이라는 뜻은 아니며, 오프라인에 쌓인 변화는 재연결한 주에 반영될 수 있습니다.
- **내 서버 공유 정보 삭제**를 실행하면 친구 관계뿐 아니라 소셜 채팅·응원·파티·주간 점수 자료도 해당 계정과 관련된 항목이 삭제됩니다. Supabase Auth 익명 사용자는 별도로 남을 수 있습니다.
- 모바일 브라우저 데이터 초기화·앱 삭제 시 익명 계정을 복구하지 못할 수 있으니 주의하세요.

## 테스트

1. 두 기기에서 각자 친구 탭의 실시간 연결을 확인합니다.
2. A가 B에게 **파티 초대**를 보내고 B가 **수락**한 뒤, 각각 퀘스트 1개씩 완료합니다. 두 사람의 파티 진행이 2개로 늘어나는지 확인합니다.
3. A가 B에게 **응원**을 보내고 B의 **알림**에서 수신을 확인합니다.
4. A가 B에게 **안녕!** 메시지를 보내고 B의 채팅에서 도착하는지 확인합니다.
5. 두 사람 중 한 명이 퀘스트를 완료하고 **랭킹**에서 주간 XP가 반영되는지 확인합니다.
6. 테스트용 메시지의 **신고** 버튼과 차단/차단 해제 UI 위치를 확인합니다. 실제 차단은 친구 관계가 해제되므로 필요할 때만 사용하세요.

기능에 오류가 난다면 앱의 친구 화면에 나타나는 오류 메시지를 확인하세요. 특히 `PGRST202` 또는 'relation does not exist' 오류는 마이그레이션 SQL을 실행하지 않았거나 다른 프로젝트에서 실행했을 가능성이 있습니다.
